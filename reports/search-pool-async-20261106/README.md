# 搜索池异步化与集中状态验证（2026-11-06）

已部署到现有 `http://127.0.0.1:18083/search`。训练、评测、数据生产继续使用同一份实现与接口；三类真实客户端已在隔离模拟服务中回归。

## 实现和边界

- `serper_proxy.py`：aiohttp 异步连接池；保留原 Serper 返回结构和结构化错误。
- `search_pool_state.py` + `search_pool_scripts/state.lua`：Redis 原子队列、全局/每 key 速率与并发、租约续期和 fencing、隔离、结果缓存、审计事件。
- worker 丢失后，未发送任务恢复排队；已发送但结果未知的任务不自动重发，计入 billing_unknown。超时后的 key 槽位保留至租约到期。
- 可选 `Idempotency-Key` 支持跨副本去重。TTL 默认一小时；无该请求头的两次 HTTP 请求视为不同操作。无法承诺外部供应商的绝对 exactly-once 计费。
- Redis AOF `appendfsync always`、`noeviction`；Redis 不可用时拒绝无控制的上游请求。当前为单机 Redis，不是 HA 集群。
- 排队默认最多 45 秒，和执行共同受原始 60 秒客户端总预算约束。worker 恢复不会刷新整个执行预算。
- 正式全局执行上限 1024、额外等待队列 1024、本机 worker 槽位 128。上游仍受每 key 2 并发/2 RPS 限制。

## 持续负载验证

1024 条合成轨迹，每条 **24 次顺序搜索**：完成 1024 条，成功调用 24,576 次，耗时 51.34 秒；成功率 100%，重复模拟计费 0。排队 P95/P99 为 **7.089/11.605 秒**；合成轨迹/小时外推 71,805。这不代表小时级稳定性验证，也不能将短时的 P99 当作持续负载 SLA。

在初版 httpx 服务连接池的持续测试中出现 2 次传输失败（无自动重发、无重复计费），详见 `soak-httpx-before.json`。压测客户端也出现过连接读取失败。最终服务与压测客户端均使用 aiohttp，重新完成全档位和持续负载验证。未对所有失败逐一做内核级归因，不能将该结果概括为所有场景下 httpx 不可用。

## 正式迁移和真实额度验证

- 原端口不变，旧进程在 pending=0 时退出；Redis 与新服务已启动。
- 迁移前后均为 **97 个 key、57 个可用、40 个 quota_exhausted 隔离**。旧用量计数也已导入；私有迁移快照在 runtime/archive，未提交凭据。
- 当前配置下单机上游并发理论上限为 min(128 worker, 1024 全局, 57×2 key) = **114**，不是 1024 个真实上游请求；供应商账号级限制还可能更低。
- 真实测试最多 5 次 HTTP 调用：4 个独立搜索 + 1 次幂等重放。全部 HTTP 200，审计记录实际 4 次上游尝试，响应确认合计 **4 credits**，幂等重放未新增上游调用，billing_unknown=0。
- 真实探针第一次汇总使用了 Redis 6.0 不支持的排他 XRANGE 起点。已修复并通过模拟回归；正式结果从已有持久审计记录和 5 条 HTTP 200 日志恢复，**没有为补报告再次消耗额度**。原始客户端延迟采样未保留，报告未伪造此项。
- `real-probe.json`、`migration.json`、`live-health.json` 保留证据。credits 来自供应商响应，未独立核对账号余额或账单。

## 运维

正式入口和说明见 `Evaluation/services/README.search-pool.md`。

```bash
python Evaluation/services/search_pool.py check
# 更新私有 keys.json 后，显式发布给所有副本：
bash Evaluation/services/start_search_pool.sh sync-keys
# 原 key 充值后，使用完整 SHA256 指纹在线恢复：
bash Evaluation/services/start_search_pool.sh restore-key --key-id FULL_SHA256
```

编辑旧 key-state.json 不会改变 Redis 中的当前状态；编辑 keys.json 后须执行 sync-keys。修改准入配置须先排空并停止全部副本，再执行 configure、重启副本。新增实现仅在正式 services 目录，模拟负载工具在 scripts/validation，结果在 reports，下载依赖与诊断日志在 .cache，凭据与 AOF 在私有 runtime。
